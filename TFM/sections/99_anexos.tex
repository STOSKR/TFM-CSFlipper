\chapter{Anexos}

\section{Estructura del repositorio}

El repositorio se organiza como un monorepo. La carpeta \texttt{apps} contiene aplicaciones y comandos ejecutables. La carpeta \texttt{packages} contiene la lógica reutilizable. La carpeta \texttt{docs} recoge decisiones y documentación técnica. La carpeta \texttt{tests} contiene pruebas unitarias e integración. La carpeta \texttt{backlog} mantiene el estado de tareas realizadas, pendientes y en progreso.

Los módulos principales son:

\begin{itemize}
  \item \texttt{apps/acquisition}: extractores, scraping, OCR, importadores y SteamDT.
  \item \texttt{apps/cli}: comandos de construcción de datasets, entrenamiento, scraping y evaluación.
  \item \texttt{packages/contracts}: contratos Pydantic compartidos.
  \item \texttt{packages/persistence}: conexión, repositorios y persistencia.
  \item \texttt{packages/prediction}: entrenamiento e inferencia supervisada.
  \item \texttt{packages/simulation}: reglas económicas, cartera, riesgo y backtesting.
  \item \texttt{packages/marl}: entorno multiagente, wrappers PettingZoo/RLlib y entrenamiento.
  \item \texttt{packages/vision}: OCR, preprocesado y parsing visual.
\end{itemize}

\section{Configuración del entorno}

El entorno se define en \texttt{pyproject.toml}. El proyecto usa Python, Supabase/Postgres, Pytest, Ruff, Mypy y dependencias opcionales para MARL como Ray/RLlib, PettingZoo, Gymnasium y PyTorch. Para desarrollo local existe un \texttt{docker-compose.yml} con Postgres.

Comandos representativos:

\begin{verbatim}
python -m pytest tests/unit
python -m ruff check
python -m mypy apps packages tests/unit
python scrape_flow.py --show-browser --persist
python -m apps.cli.auto_scrape_loop --once
\end{verbatim}

\section{Parámetros de entrenamiento}

Los experimentos supervisados usan splits temporales, calibración de probabilidades y selección por precisión operativa en umbrales altos. En los smoke tests se compararon modelos dummy, regresión logística, random forest e histogram gradient boosting. El entrenamiento MARL usa RLlib con un entorno multiagente y tres políticas: Scout, Trader y Portfolio.

\section{Modelo de datos}

El modelo operativo actual gira alrededor de dos tablas principales: \texttt{market\_items} y \texttt{market\_history\_points}. La primera representa variantes reales de artículos y su estado actual por plataforma. La segunda almacena series temporales en formato largo, con una fila por artículo, plataforma, fecha y métrica. Esta estructura evita mezclar métricas distintas y permite añadir nuevas señales sin alterar la forma general del histórico.

\section{Pruebas implementadas}

El proyecto incluye pruebas para parsing de mercado, OCR, persistencia, datasets supervisados, entrenamiento supervisado, simulador de cartera, riesgo, entorno MARL, wrappers RLlib y flujos de scraping. La suite se ejecuta de forma recurrente con Pytest, Ruff y Mypy.

\section{Resultados adicionales}

Los resultados intermedios se guardan en \texttt{model-runs} y los datasets derivados en \texttt{data/datasets}. Estas carpetas permiten conservar reportes de cobertura, exploración de características, métricas de entrenamiento, umbrales seleccionados y salidas de smoke tests sin mezclar los artefactos pesados con el código principal.
